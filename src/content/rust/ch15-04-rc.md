一个值有多个所有者时用 `Rc<T>`。强引用计数到 0 才清理，避免还有人用时被释放。

适合堆上的数据被多处只读共享，且编译期不知道谁最后用完。若能确定最后使用者，用普通所有权即可。

`Rc<T>` 不是线程安全的，只用于单线程。多线程用 `Arc<T>`。

### 共享数据

两条列表要共享第三条的所有权。`Box<T>` 独占，做不到。

**清单 15-17** 两个 `Box` 列表试图共用第三个列表，不能编译。

**对照**：`Rc<T>` 接近不带原子操作的 C++ `shared_ptr`。`clone` 加的是计数，不是 Java / Python 那种再复制一份引用就完事。

```rust
enum List {
    Cons(i32, Box<List>),
    Nil,
}

use crate::List::{Cons, Nil};

fn main() {
    let a = Cons(5, Box::new(Cons(10, Box::new(Nil))));
    let b = Cons(3, Box::new(a));
    let c = Cons(4, Box::new(a));
}
```

`Cons` 拥有内部数据。构造 `b` 时 `a` 被移进去，再拿 `a` 构造 `c` 就是使用已移动的值。

改成存引用要写生命周期，并要求每一项至少活得和整份列表一样久，不是所有场景都成立。

改用 `Rc<List>`：`Rc::clone` 只把强引用计数加一，不深拷贝。计数不为 0 就不释放。

**清单 15-18** 用 `Rc<T>` 定义可共享的 `List`。

```rust
enum List {
    Cons(i32, Rc<List>),
    Nil,
}

use crate::List::{Cons, Nil};
use std::rc::Rc;

fn main() {
    let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
    let b = Cons(3, Rc::clone(&a));
    let c = Cons(4, Rc::clone(&a));
}
```

`Rc` 不在预导入里，要 `use std::rc::Rc`。

约定写 `Rc::clone(&a)`，不写 `a.clone()`。`Rc::clone` 只加计数；别的类型的 `clone` 常常是深拷贝。查性能时可以忽略 `Rc::clone`。

### 克隆会增加引用计数

**清单 15-19** 在创建和离开作用域时打印 `Rc::strong_count`。

```rust
// --snip--

fn main() {
    let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
    println!("count after creating a = {}", Rc::strong_count(&a));
    let b = Cons(3, Rc::clone(&a));
    println!("count after creating b = {}", Rc::strong_count(&a));
    {
        let c = Cons(4, Rc::clone(&a));
        println!("count after creating c = {}", Rc::strong_count(&a));
    }
    println!("count after c goes out of scope = {}", Rc::strong_count(&a));
}
```

`Rc::strong_count` 读强引用数。另有 `weak_count`（`Weak<T>`）。离开作用域时 `Drop` 自动减计数，不用手动减。

`Rc::clone` 加一，离开作用域减一，强计数到 0 才释放。任一所有者还在，值就保持有效。

`Rc<T>` 只提供不可变共享。要在共享的同时修改，下一节用 `RefCell<T>`。
